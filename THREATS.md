# LedgerLine Threat Model & Mitigation Matrix

This document tracks security threats, mitigations, verification tests, and their current implementation status for LedgerLine.

| Threat | Mitigation | Test | Status |
|---|---|---|---|
| **1. Weak JWT Secret** (HMAC brute-force or dictionary attack) | `JwtService` validates secret length on application startup (`@PostConstruct`) and aborts startup with an `IllegalStateException` if `JWT_SECRET` is missing, blank, or shorter than 32 bytes (256 bits). Algorithm is explicitly pinned to HMAC-SHA256 (`Jwts.SIG.HS256`). | `JwtStartupValidationTest#testJwtSecretTooShortThrows` | **Handled** |
| **2. User Enumeration on Login** (side-channel timing attacks or differential error messaging) | Authentication service returns a generic `"Invalid credentials"` message for both unknown usernames and invalid passwords. Employs a constant-time comparison path by running a full 12-round BCrypt calculation against a precomputed dummy hash even when the user does not exist in the database. | `AuthSecurityIntegrationTest#testLoginFailureWrongPassword`, `testLoginFailureUnknownUser` | **Handled** |
| **3. Default Credentials in Production** | Zero hardcoded default passwords in code or configuration. `DatabaseSeeder` mandates `SEED_ADMIN_PASSWORD`, `SEED_HOLDER_PASSWORD`, and `SEED_AUDITOR_PASSWORD` via environment variables and terminates startup immediately if any are missing or blank. | `JwtStartupValidationTest#testDatabaseSeederFailsWhenPasswordMissing` | **Handled** |
| **4. Application Role Owns Tables (Privilege Escalation & Tampering)** | Principle of least privilege enforced at the PostgreSQL layer: migrations run as `ledger_owner`, while the application connects as restricted `ledger_app`. `ledger_app` does not own any table and is explicitly revoked and denied `UPDATE`, `DELETE`, and `TRUNCATE` permissions on `ledger_entries`, `postings`, `ledger_attempts`, and `audit_log`. | `DatabaseRolePermissionsIntegrationTest#testAppCannotUpdateLedgerEntries`, `testAppCannotDeleteLedgerEntries`, `testAppCannotTruncateLedgerEntries` | **Handled** |
| **5. Secrets Committed to Source Control (Git)** | `.gitignore` excludes `.env`, `.env.local`, `.idea`, build artifacts, and local tool configs. `application.yml` uses environment variable placeholders without hardcoded credentials. A `.env.example` template with dummy values is provided. | Git status verification and repository inspection | **Handled** |
| **6. Stack-Trace and Exception Class Leakage** | `server.error.include-stacktrace=never` and `server.error.include-message=never` in `application.yml`. A global `@RestControllerAdvice` (`GlobalExceptionHandler`) intercepts all checked and unchecked exceptions, returning sanitized, generic JSON error envelopes without internal class names or database details. | `AuthSecurityIntegrationTest#testLoginFailureWrongPassword` | **Handled** |
| **7. Brute-Force Login Attacks** (credential stuffing) | Account lockout / IP rate limiting (e.g. token bucket algorithm or Redis-backed sliding window counter) to throttle repeated failed login attempts. | Planned Task 4 integration test suite | **Planned (Task 4)** |
| **8. XSS Stealing Authentication Token** | Single-page application stores JWT strictly in React component memory state, completely avoiding `localStorage` and `sessionStorage`. **Tradeoff**: session is cleared upon browser refresh or tab closure; long-lived sessions require silent refresh with HttpOnly cookies. | Architecture review & frontend memory storage design | **Handled (tradeoff documented)** |
| **9. Permissive / Allow-by-Default Routing** | Strict deny-by-default HTTP security configuration via Spring Security: `.anyRequest().authenticated()`. Only `/api/auth/login`, `/actuator/health`, and static assets are permitted publicly. Method security (`@EnableMethodSecurity`) enforces role-based authorization on sensitive routes. | `AuthSecurityIntegrationTest#testProtectedRouteRequiresToken`, `testHolderCannotAccessAdminEndpoint`, `testAdminCanAccessAdminEndpoint` | **Handled** |
| **10. Mass-Assignment of Role on User Creation** | No public user registration endpoint. Seed and internal user creation strictly bind the `UserRole` enum within service logic. No external API payload accepts role manipulation parameters. | Architecture review & DTO inspection | **Handled** |
